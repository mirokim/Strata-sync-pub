## 5. 카테고리별 상세 분석

### 5.1 A — 정확 키워드 (60건): 예상 PASS 90%

**결론**: 문서 제목의 핵심 키워드를 그대로 사용하면 BM25가 잘 동작함. 파일명 매칭 부스트(+2.0)와 높은 IDF가 결합되어 정확도가 높음.

**잔여 리스크**:
- Confluence ID 프리픽스(`192868302_`)가 토큰화에 간섭 가능 → 실제 영향은 미미
- 한자어+영문 혼합 파일명에서 토큰 분리 불완전한 케이스 존재

---

### 5.2 B — 동의어/약어 (70건): 예상 PASS 36%

**핵심 문제점**:

1. **동의어 맵 커버리지 부족** — 현재 ~50개 항목만 존재
   - 누락: `세이프존↔안전지대`, `온보딩↔튜토리얼`, `몹↔NPC/몬스터`, `궁극기↔얼티밋`, `리포트↔보고`, `경영진↔이사장`
   
2. **단방향 매핑** — 일부 동의어가 한 방향으로만 작동
   - `음향→사운드` (작동) vs `오디오→사운드` (미등록)
   
3. **추상화 수준 불일치** — 상위 개념어가 하위 문서를 찾지 못함
   - `외주 업체` → `외주 서칭 현황` (부분 매칭)
   - `아웃소싱` → 0건 (매핑 없음)

**개선 제안**:
```
추가 필요한 동의어 쌍 (우선순위 높음):
세이프존 ↔ 안전 지대 ↔ safe zone
온보딩 ↔ 튜토리얼 ↔ 신규 교육
몹 ↔ 몬스터 ↔ NPC ↔ 적
궁극기 ↔ 얼티밋 ↔ 필살기 ↔ ultimate
리포트 ↔ 보고 ↔ 보고서
임원 ↔ 이사장 ↔ 의장 ↔ 경영진
외주 ↔ 아웃소싱 ↔ 협력사
레벨 ↔ 맵 ↔ 스테이지
데모 ↔ 시연 ↔ 프레젠테이션
버그 ↔ 이슈 ↔ 결함
```

---

### 5.3 C — 영한 혼용 (60건): 예상 PASS 20%

**치명적 약점**: 영문 전용 쿼리로 한글 문서를 찾는 것이 거의 불가능.

**실측 결과**:
- `daizan skill` → skill_table.md (다이잔 관련 문서 0건)
- `character balance` → HDRP 기능 문서 (완전 무관)
- `conquest mode rules` → damage_table.md (무관)
- `scarlet concept` → Virtuos 문서 (무관)

**예외적으로 작동하는 케이스**:
- 영문 파일명이 있는 경우: `Heroes of the Storm`, `Virtuos`, `RadiantGI`
- 영문 테이블명: `quest_reward_table`, `skill_table`, `character_stat_table`
- 원래 영문인 고유명사: `Passive Skill`, `SDF`, `HDRP`

**개선 제안**:
- 캐릭터명 영한 매핑 테이블 추가: `daizan↔다이잔`, `scarlet↔스칼렛`, `matini↔마티니`
- 게임 용어 영한 매핑: `conquest↔점령전`, `brawl↔난투전`, `skill↔스킬`, `balance↔밸런스`
- 쿼리 전처리에 영→한 번역 레이어 추가 검토

---

### 5.4 D — 자연어 질문 (80건): 예상 PASS 50%

**분석**: 자연어 질문에서 "~은 어떤", "~가 뭔가요", "알려줘" 같은 메타 표현은 BM25에서 노이즈로 작용하지만, 핵심 키워드가 포함되면 대체로 작동함.

**PASS 패턴**: 핵심 고유명사 + 문서 유형 키워드
- "다이잔 스킬은 어떤 것들이 있나요" → `다이잔`, `스킬` 매칭 → ✅
- "레이드 보스 우로보 전투 방식은" → `레이드`, `보스`, `우로보`, `전투` 매칭 → ✅

**FAIL 패턴**: 추상적 의도 + 약한 키워드
- "뭘 만들고 있는 거야" → 의미 있는 키워드 없음 → ❌
- "이번 분기에 뭘 집중하고 있나요" → `분기`, `집중` 은 문서에 희소 → ⚠️

**개선 제안**:
- 슬랙봇의 query rewriting 단계에서 불용어 제거 강화
- 의도 분류기 추가: "목록 질의" / "특정 문서 질의" / "비교 질의" / "현황 질의"

---

### 5.5 E — 오타/철자 변형 (40건): 예상 PASS 20%

**치명적 약점**: BM25는 정확한 토큰 매칭 기반이므로 오타에 극도로 취약.

**실측 결과**:
- `프시게` (오타) → score 2.6 (정답 `프시케` → score 10.5) — **75% 점수 하락**
- `마티니 자블린` vs `재블린` — 한 글자 차이로 매칭 실패

**특히 위험한 패턴**:
- 외래어 표기 차이: `쉐이더/셰이더`, `데미지/대미지`, `밸런스/발란스`
- 한글 초성 오타: `프시게/프시케`, `이팩트/이펙트`
- 영문 약어 한글화: `엠8/M8`, `엔피씨/NPC`, `피브이피/PVP`
- 띄어쓰기 차이: `점령전/점령 전`, `난투전/난투 전`

**개선 제안**:
- 외래어 표기 변형 테이블 추가 (쉐이더↔셰이더, 데미지↔대미지)
- 한글 초성 기반 fuzzy 매칭 도입 검토
- 영문 약어 한글화 매핑 (M8↔엠8, NPC↔엔피씨)
- 자모 분해 기반 편집거리 계산 (Levenshtein on jamo)

---

### 5.6 F — 시간 기반 (50건): 예상 PASS 40%

**분석**: BM25는 시간 범위 필터링을 지원하지 않음. 연도가 파일명이나 본문에 포함된 경우에만 키워드로 매칭.

**작동 패턴**:
- 파일명에 날짜 포함: `250307 BR모드` → 정확 매칭 ✅
- 연도가 명시적: `회의록 2022` → 파일명 매칭 ✅
- `M8`, `M12` 등 마일스톤 코드 → 정확 매칭 ✅

**실패 패턴**:
- 상대적 시간: `최근`, `작년`, `이번 주` → BM25로 해석 불가 ❌
- 기간 범위: `2021년 하반기` → "하반기"가 문서에 없으면 실패 ❌
- 불완전한 날짜: `22년` → "2022"와 매칭 안 됨 ❌

**개선 제안**:
- 쿼리 전처리에서 `22년` → `2022` 정규화
- `최근` → 최근 6개월 문서 부스트 (이미 recency boost 있으나 효과 미미)
- `작년` → 현재연도-1 치환
- 날짜 범위 필터 도입: `from:2021-07 to:2021-12`

---

### 5.7 G — 다중 조건 (50건): 예상 PASS 44%

**분석**: 조건이 많을수록 coverage penalty가 유리하게 작용하여 정확도 상승. 단, 5개 이상 토큰에서 부분 매칭 문서가 페널티를 받아 recall 하락.

**개선 제안**: Coverage penalty 임계값을 동적으로 조정 (쿼리 토큰 수 비례)

---

### 5.8 H — 모호/추상 (40건): 예상 PASS 25%

**분석**: BM25의 구조적 한계. 의미론적 이해 없이 토큰 빈도로만 판단하므로, 추상적 질의에서 IDF가 낮은 범용 단어만 매칭됨.

**개선 제안**: 벡터 검색 강제 활성화 필요. 모호한 쿼리일수록 임베딩 기반 시맨틱 매칭이 유효.

---

### 5.9 I — 부정/비교 (20건): 예상 PASS 20%

**분석**: BM25는 부정 연산자(`NOT`, `~이 아닌`)를 지원하지 않음. 비교 질의는 양쪽 대상의 문서를 모두 반환하나 "비교" 자체를 수행하지 못함.

**개선 제안**: 비교 질의 감지 → 양쪽 대상 별도 검색 후 LLM 합성

---

### 5.10 J — 도메인 전문용어 (30건): 예상 PASS 60%

**분석**: 프로젝트 고유 용어(`클루`, `융기`, `운기`, `가레벨`)는 문서에서도 동일 표기를 사용하므로 BM25 매칭이 잘 됨. 반면 일반 게임 개발 용어(`CC기`, `어그로`, `나비메시`)는 문서 내 사용 빈도에 따라 다름.

## 18. E2E에서 발견된 핵심 문제점

### 18.1 검색은 되지만 답변이 안 되는 문제 (RAG 컨텍스트 부족)

```
사례: "다이잔 스킬" → 검색에서 다이잔 관련 문서를 찾지만,
      RAG 컨텍스트에 포함된 본문이 "사운드 리스트"여서
      LLM이 "스킬 종류를 확인하기 어렵다"고 답변.
```

**원인**: 검색 결과 Top-K 문서의 본문 중 첫 2,000자만 컨텍스트에 포함. 핵심 정보가 파일 후반에 있으면 누락.

**영향**: A 카테고리(정확 키워드)에서도 WEAK 발생

### 18.2 동의어 미확장 → 검색 자체 실패 (기대대로)

```
사례: "세이프존" → 동의어 미확장 → 안전 지대 문서 못 찾음 → "문서에 없다"
      "컨퀘스트" → 동의어 미확장 → 점령전 문서 못 찾음 → "문서에 없다"
      "엠8" → M8로 변환 안 됨 → 못 찾음
```

**해결**: 동의어 확장 코드 이미 적용 완료. MCP 서버 재시작하면 해결.

### 18.3 영문 쿼리는 RAG 파이프라인이 부분적으로 보완

```
기대 FAIL이었으나 실제 PASS:
  "character balance" → LLM이 맥락에서 밸런스 관련 내용을 추출해 답변
  "quest reward" → 영문 테이블명이 정확히 매칭되어 상세 답변
  "world building" → 세계관 문서가 검색되어 국가/종족 상세 답변
  "meeting minutes 2025" → 회의록 문서 검색되어 핵심 요약

기대대로 FAIL:
  "daizan skill" → 다이잔이 토큰에 없어 검색 자체 실패
  "scarlet concept" → 스칼렛 매핑 없어 검색 실패
  "conquest mode rules" → 점령전 매핑 없어 검색 실패
```

**분석**: 영문 쿼리의 E2E PASS율이 BM25(20%)보다 훨씬 높은 56%인 이유:
1. 영문 파일명이 있는 문서는 직접 매칭 (quest_reward_table 등)
2. 세계관, 회의록 등은 본문에 영문 키워드가 포함되어 간접 매칭
3. LLM이 부분 컨텍스트에서도 관련 정보를 추출하는 능력

### 18.4 모호/추상 질의에서 LLM이 큰 폭으로 보완

```
BM25에서 FAIL이었으나 E2E에서 PASS:
  "경쟁작 대비 장점" → BM25로는 명확한 문서 매칭 불가,
    하지만 RAG 컨텍스트에 레퍼런스 분석 문서가 포함되어
    LLM이 "지형 파괴, 블록 샌드박스, 유니크 세계관" 추출

  "초보자 경험 개선" → BM25 FAIL이었으나
    튜토리얼/온보딩 관련 컨텍스트에서 LLM이 구체적 제안 생성

  "현재 프로젝트 상황" → BM25로는 불명확했으나
    피드백 히스토리에서 LLM이 프로젝트 현황 종합
```

**분석**: 모호 질의 E2E PASS율 67% (BM25: 25%) — **+42%p 개선**. LLM의 종합/추론 능력이 검색 품질 한계를 크게 보완.

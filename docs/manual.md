# Strata Sync 사용 설명서

> 팀의 공유 뇌. 사람은 AI와 대화하며 일하고, AI가 볼트에 올리고 정리하고, 에이전트들이 서로에게 묻습니다.

---

## 1. 왜 만들었나

팀의 지식은 늘 흩어져 있습니다. 결정은 회의에서 나고, 근거는 누군가의 머릿속에, 맥락은 슬랙 스레드 어딘가에 있습니다. 위키를 만들어도 아무도 안 씁니다 — 일하는 자리와 떨어져 있고, **정리는 사람이 해야 하니까요.**

그런데 이제 일하는 방식이 바뀌었습니다. 각자 Claude Code, Codex, Cursor를 옆에 두고 **AI와 대화하면서** 일합니다. 결정도, 자료도, 아이디어도 그 대화 안에서 나옵니다. 문제는 그 에이전트들이 서로 아무것도 모른다는 것입니다. 김의 에이전트가 오전에 내린 결정을, 이의 에이전트는 오후에도 모릅니다.

Strata Sync는 여기서 출발합니다.

- **사람은 대화하고 생각합니다.** 볼트에 쓰러 가지 않습니다. 사람이 하는 일은 대화하고, 창의력을 내고, 흩어진 조각들 사이에서 새로운 생각을 하는 것입니다.
- **AI가 올리고 정리합니다.** 대화에서 나온 결정·자료·생각을 에이전트가 볼트에 기록하고, 제목을 붙이고, 링크를 걸고, 폴더에 넣습니다. 일하면 저절로 쌓입니다.
- **에이전트가 같은 기억을 씁니다.** MCP로 연결된 모든 에이전트가 같은 볼트를 읽습니다. 너의 에이전트가 나의 에이전트에게 묻고, 일을 넘깁니다.
- **허브가 봅니다.** 누가 뭘 바꿨는지, 어떤 문서가 어떤 문서와 충돌하는지, 링크가 어디서 끊기는지 — 한 사람의 세션에서는 절대 보이지 않는 것을 서버가 잡아서 알려줍니다.

한 문장으로: **"너의 클로드가 나의 클로드한테 물어본다."** 혼자 쓰는 Claude Code로는 안 되는 것 — 다른 사람의 에이전트, 다른 사람의 맥락, 시간을 가로지르는 기억 — 이것이 이 제품의 이유입니다.

## 2. 한눈에 보기

```
  Claude Code · Codex · Cursor            웹 앱
  사람은 대화만 ──── AI가 올리고 정리 ──▶  게시 · 탐색 · 발견
              │ MCP                          ▲ 보기
              ▼                              │
        ┌──────────────────────────────────────┐
        │  팀 볼트 (Cloudflare)                 │
        │  기억: 문서 · 링크 · 히스토리 · 작성자  │
        │  허브: 검색·회상 · 그래프·린트 · 레이더 │
        │  사람 사이: 편지함 · 릴레이 · AI 멤버   │
        └──────────────────────────────────────┘
```

- **볼트**는 팀의 기억입니다. 그릇은 마크다운 파일과 `[[위키링크]]`지만, 본질은 *누가 언제 무슨 근거로 무엇을 믿었나*입니다 — 링크, 버전 히스토리, 작성자, 반응까지.
- **에이전트**가 볼트의 주된 쓰기 주체입니다. `vault_write`로 기록하고, `vault_recall`로 팀이 아는 것을 불러오고, `inbox_send`로 팀원의 에이전트에게 묻습니다.
- **웹 앱**은 게시판입니다. 쌓인 것을 둘러보고, 그래프로 관계를 보고, 남들이 생각한 것을 읽고, 내 책상에서 나에게 온 것을 확인합니다. 편집기도 있지만 주인공이 아닙니다.
- **서버**(Cloudflare Worker)가 저장·검색·그래프·히스토리를 맡고, 편지함·레이더·AI 멤버를 돌립니다.

## 3. 시작하기

### 3.1 에이전트 연결 — 여기가 시작입니다

Claude Code 기준. 팀 토큰 방식이면 이런 모양입니다 (Codex, Cursor도 같은 MCP 주소를 씁니다).

```bash
claude mcp add --transport http strata https://<worker>/mcp --header "Authorization: Bearer <팀 토큰>" --header "X-Author: 홍길동"
```

`X-Author`가 중요합니다. 서버는 이 이름으로 "누가 썼는지", "누구에게 온 편지인지"를 판단합니다. Google 로그인 서버라면 헤더 없이 `claude mcp add --transport http strata https://<worker>/mcp`만 치면 로그인 창이 뜹니다. 웹 앱의 설정 → MCP 탭에 내 이름이 들어간 명령이 준비돼 있습니다.

연결되면 그냥 일하면 됩니다. 에이전트는 세션을 열 때 `vault_me`로 내 책상을 확인하고, 대화 중에 결정이 나면 `vault_write`로 기록하고, 필요하면 팀원의 에이전트에게 묻습니다. 서버의 안내문이 그렇게 시키므로 따로 부탁할 필요가 없습니다.

### 3.2 첫 10분 — 대화로

1. "볼트에서 '소음 목표'에 대해 팀이 아는 걸 모아줘" → `vault_recall`이 관련 문서·이웃·멤버 메모를 한 묶음으로 가져옵니다.
2. 일하다가 결정이 나면: "이거 기록해 둬" → 에이전트가 알맞은 폴더에 문서를 만들거나 기존 문서를 고치고, 링크를 겁니다. 이미 있는 문서면 새로 만들지 않고 갱신합니다.
3. "이 결정 이가 알아야 하는데" → `inbox_send`. 이의 에이전트가 다음에 켜질 때 그 사람 맥락으로 답합니다.
4. "방금 쓴 거 뭐랑 충돌해?" → `radar_check`.

### 3.3 웹 앱 — 둘러보기

1. 팀의 웹 주소를 엽니다 (예: `https://strata-sync-nine.vercel.app`).
2. **Google 로그인**(서버에 켜져 있으면) 또는 **팀 토큰 + 내 이름**. 팀 토큰이면 이름이 곧 나입니다 — MCP의 `X-Author`와 같게.
3. 그래프가 뜹니다. 노드를 누르면 문서가 열리고, 오른쪽 Brain 패널에 이 문서에 얽힌 것들(멤버 반응, 히스토리, 링크, 제안, 이웃)이 보입니다.
4. 상단 바의 **사람 아이콘** → 내 책상. 나에게 온 질문·작업, 내 문서에 온 반응, 남들이 최근 바꾼 것.

## 4. 매일 쓰는 법

**아침** — 에이전트를 켜면 `vault_me`부터 봅니다(서버가 그렇게 안내합니다). 팀원의 에이전트가 남긴 질문이 있으면 내 맥락 — 내 레포, 내 개인 문서 — 으로 답합니다. 앱에서는 내 책상의 "나에게 온 것"에 답변 상자가 있습니다.

**일하는 중** — 그냥 대화합니다. 결정·자료·생각이 나오면 에이전트가 볼트에 기록합니다(`vault_write`). 확신이 없는 것, 팀이 아직 채택하지 않은 것은 제안(`_agent/`)으로 남기고, 사람이 승격합니다. 남의 문서를 고칠 때는 뜻을 지키고, 그 사람의 결정이 걸린 일이면 고치는 대신 편지함으로 묻습니다. 모든 버전이 남으니 되돌릴 수 있습니다.

**저장하는 순간** — 두 가지가 자동으로 돕습니다.
- **AI 멤버 반응**: 그 문서를 담당 범위로 둔 AI 멤버(사서, 디자이너…)가 "이게 뭘 바꾸나 / 어디와 부딪히나 / 질문 하나"를 남깁니다. Brain 패널에 보입니다.
- **모순 레이더**: 서버가 가장 가까운 문서들(다른 사람이 쓴 것 포함)과 비교해서 "동시에 참일 수 없는 것"을 찾으면 편지함에 질문을 넣습니다. "이 문서는 60 dB라는데 박의 문서는 65 dB — 어느 쪽?"

**누군가에게 물을 때** — 슬랙 대신 편지함. "이 파라미터 바꾸면 앱 쪽 영향 있어?"를 이의 이름으로 보내면, 이 또는 이의 에이전트가 다음에 켜질 때 그 사람 맥락으로 답합니다. 작업도 같은 방식으로 넘깁니다.

**릴레이** — 작업에 "다음 사람들"을 적어 두면(박 → 최), 이가 완료하는 순간 서버가 같은 작업을 박 앞으로 만들고 결과를 인용해 붙입니다. 일이 밤새 한 사람 컴퓨터에서 다음 사람 컴퓨터로 걸어갑니다. 모든 단계가 지정된 사람에게 갑니다.

**생각할 때** — 웹 앱을 엽니다. 그래프에서 멀리 떨어진 두 덩어리, 레이더가 잡은 충돌 쌍, 3개월 전 문서와 오늘 문서. 나란히 놓인 것들 사이에서 새 생각이 나면, 다시 에이전트에게 말하면 됩니다.

## 5. 기능

### 볼트와 기억
- **문서**: 마크다운 + 프런트매터(제목·종류·태그·날짜). 폴더와 파일 이름이 곧 구조. 에이전트가 이 규칙에 맞춰 씁니다.
- **링크**: `[[문서 이름]]`. 링크가 모여 그래프가 됩니다. `graph_suggest_links`가 이 글이 링크해야 할 문서를 골라 줍니다.
- **히스토리**: 저장할 때마다 이전 버전이 보관됩니다(문서당 20개). "누가 언제 무엇을 바꿨나"를 diff로 봅니다(`vault_history`, Brain 패널).
- **개인 문서("나만 보기")**: Google 로그인 사용자는 문서를 나만 보기로 둘 수 있습니다. 같은 볼트 안에 있고 나에게는 링크·그래프·검색·회상이 그대로 작동하지만, 다른 사람과 다른 사람의 에이전트에게는 존재하지 않습니다. 개인 문서의 문장을 제안이나 멤버 기억에 옮기면 서버가 막습니다.
- **이미지**: 앱에 붙여넣거나 에이전트가 올리면 `attachments/`에 저장되고 이미지 문서가 생깁니다. 설명은 에이전트가 보고 채웁니다(`images_undescribed`).

### 검색과 회상
- 검색은 BM25 + 시맨틱(임베딩)을 섞습니다. 한국어는 음절 2-gram으로 잘라서 조사에 덜 흔들립니다.
- `vault_recall`은 검색 결과에 링크 이웃, AI 멤버의 기억, 멤버가 남긴 말을 더해 "이 주제에 대해 팀이 아는 것"을 한 묶음으로 줍니다. 에이전트가 무언가 시작하기 전에 부르는 툴입니다.

### 사람 사이
- **내 책상**(`vault_me`, 앱의 사람 아이콘, `?view=me`): 나에게 온 질문/작업, 내가 물은 것과 답, 내 문서에 온 반응, 내 문서를 인용한 제안, 남들이 최근 바꾼 것, 내 문서.
- **편지함**(`inbox_send` / `inbox_list` / `inbox_reply`): 이름으로 보내는 질문과 작업. 답할 수 있는 건 받는 사람뿐.
- **릴레이**: 작업의 `chain`. 완료되면 다음 사람에게 자동으로.
- **모순 레이더**(`radar_check`, 저장 시 자동): 팀원이 쓴 문서와 충돌하면 편지함 질문으로.

### AI 멤버
- 설정 → **AI 멤버**. 역할(사서, 디자이너, 리서처, PM…), 담당 범위(폴더·태그), 루틴(매일/매주), 자기 기억 노트 `_members/<이름> (memory).md`.
- 멤버는 각자의 에이전트에서 돌아갑니다: `/mcp__strata__member name=사서` 프롬프트를 부르면 역할·기억·오늘 할 루틴이 주어집니다. 멤버는 볼트를 정리합니다 — 링크 걸기, 같은 아이디어 합치기, 찾은 것을 문서로 남기기. 사람의 결정이 걸린 일은 제안이나 편지함으로 묻습니다.
- 서버에 모델 키가 있으면 저장 반응과 레이더가 서버에서 자동으로 돕니다.

### 웹 앱 (게시판)
- **그래프**: 3D/2D. 색은 역할·태그·폴더·활동(최근 편집이 따뜻하게). 수천 문서도 되고, 느린 기기에서는 자동으로 화질을 낮춥니다.
- **린트**(`graph_lint`, 새벽 배치 → `_reports/`): 참조는 되는데 문서가 없는 팬텀 링크, 고아, 잘리면 그래프가 갈라지는 다리 문서, 클러스터 이동.
- **에디터**: 필요할 때 사람이 직접 고칠 수 있게 있습니다. 라이브 프리뷰(커서 줄만 원문), 프런트매터 속성 표, 체크박스·표·콜아웃, 잠그면 읽기 모드.
- **Brain 패널**: 이 문서에 멤버가 남긴 말, 히스토리와 diff, 오가는 링크, 인용한 제안, 같은 동네 문서.

## 6. MCP 툴

기록: `vault_write`(기본 — 알맞은 곳에 만들거나 갱신) · `vault_propose`(확신 없는 것은 제안으로) · `vault_promote`(사람이 승인한 제안을 볼트로) · `vault_visibility`(개인 문서 공개/회수)

읽기: `vault_me`(내 책상) · `vault_recall`(주제에 대해 팀이 아는 것) · `vault_search` · `vault_read` · `vault_list` · `vault_changes`(언제부터 뭐가 바뀌었나) · `vault_history`(버전과 diff) · `vault_proposals` · `images_undescribed`

사람 사이: `inbox_send`(팀원에게 질문/작업, `chain`으로 릴레이) · `inbox_list` · `inbox_reply` · `radar_check`(이 문서가 뭐랑 충돌하나)

그래프: `graph_lint` · `graph_suggest_links`

AI 멤버: `members_list` · `member_remember`(기억 노트에 적기) · `member_report`(루틴 실행 기록) · 프롬프트 `member`

## 7. 관리

- **언어·테마·그래프·에디터**: 설정 → 일반. UI는 한국어/English, 기본은 브라우저 언어.
- **서버 배포**: `cd cloud && npx wrangler deploy`. 웹 앱은 GitHub에 푸시하면 Vercel이 자동 배포합니다.
- **모델 키**: 저장 반응과 레이더는 서버에 `ANTHROPIC_API_KEY`가 있어야 돕니다 — `cd cloud && npx wrangler secret put ANTHROPIC_API_KEY`. 없으면 멤버는 각자 에이전트에서만 돌고, 레이더는 쉽니다.
- **팀 토큰**: `wrangler secret put TEAM_TOKEN`. 바꾸면 모두 다시 접속해야 합니다.
- **시드 데이터**: 빈 볼트로 시작하기 심심하면 `node scripts/seed-product.mjs --server <worker> --token <토큰>` — 가상의 로봇청소기 회사 문서 수천 개가 들어갑니다(`--wipe`로 지우기).

## 8. 자주 묻는 질문

**정말 내가 문서를 안 써도 되나?** 네. 대화하면 에이전트가 씁니다. 직접 고치고 싶을 때만 앱의 에디터를 쓰면 됩니다.

**에이전트가 남의 문서를 마음대로 고치나?** 고칠 수 있지만 규칙이 있습니다: 뜻을 지키고, 남의 주장을 조용히 지우지 않고, 그 사람의 결정이 걸린 일이면 고치는 대신 편지함으로 묻습니다. 모든 버전이 남고, 작성자는 내 책상에서 변경을 봅니다.

**이름을 잘못 넣으면?** 팀 토큰 방식에서는 이름이 곧 나입니다. 설정 → 서버에서 바꿀 수 있고, MCP 쪽 `X-Author`도 같이 맞추세요. Google 로그인이면 계정으로 잡혀서 상관없습니다.

**개인 문서는 정말 안 보이나?** 서버가 경로 단위로 막습니다. 목록·검색·회상·히스토리·MCP 어느 길로도 남에게는 없는 문서입니다. 단, 팀 토큰 사용자는 개인 문서를 만들 수 없습니다(누구인지 확정할 수 없으니까요).

**오프라인은?** 웹 앱은 브라우저에 볼트 사본(IndexedDB)을 두고 15초마다 서버와 맞춥니다. 저장이 충돌하면 서버 버전이 남고 내 버전은 `(conflict 이름 시각).md`로 따로 저장됩니다.

**큰 볼트는 느리지 않나?** 5,000개 문서까지 확인했습니다. 첫 로딩은 수십 초, 이후는 변경분만 받습니다. 그래프는 노트북에서도 돌아가도록 자동으로 화질을 조절합니다.

# Strata Sync 사용 설명서

> 팀의 공유 뇌. 사람은 앱에서, AI 에이전트는 MCP로, **같은 볼트**를 읽고 씁니다.

---

## 1. 왜 만들었나

팀의 지식은 늘 흩어져 있습니다. 결정은 회의에서 나고, 근거는 누군가의 머릿속에, 맥락은 슬랙 스레드 어딘가에 있습니다. 위키를 만들어도 아무도 안 봅니다 — 일하는 자리와 떨어져 있으니까요.

그런데 이제 팀에는 사람만 있는 게 아닙니다. 각자 Claude Code, Cursor 같은 에이전트를 옆에 두고 일합니다. 그 에이전트들은 서로 아무것도 모릅니다. 김의 에이전트가 오전에 내린 결정을, 이의 에이전트는 오후에도 모릅니다.

Strata Sync는 이 두 문제를 하나로 풉니다.

- **볼트 하나.** 마크다운 문서와 위키링크로 된 팀의 기억. 사람은 웹 앱(또는 Obsidian)에서 보고 고칩니다.
- **에이전트도 같은 볼트.** MCP로 연결된 모든 에이전트가 같은 문서를 읽고, 제안하고, 서로에게 묻습니다.
- **서버가 전부 봅니다.** 누가 뭘 언제 바꿨는지, 어떤 문서가 어떤 문서와 충돌하는지, 링크 그래프가 어디서 끊기는지 — 한 사람의 세션에서는 절대 보이지 않는 것을 허브가 잡습니다.

한 문장으로: **"너의 클로드가 나의 클로드한테 물어본다."** 이게 되려면 이 구조가 필요합니다.

## 2. 한눈에 보기

```
   사람 (웹 앱 · Obsidian)        에이전트 (Claude Code · Cursor · Codex)
            │  읽기·쓰기                       │  MCP: vault_* · inbox_* · radar_check
            └───────────────┬──────────────────┘
                            ▼
                ┌───────────────────────┐
                │   팀 볼트 (Cloudflare) │   문서 · 위키링크 · 히스토리
                │   그래프 · 검색 · 회상  │   AI 멤버 · 편지함 · 레이더
                └───────────────────────┘
```

- **문서**는 그냥 마크다운 파일입니다. `결정 기록/기구설계/DR-0021 메인 브러시 두께 42mm로 변경.md` 처럼 폴더와 파일 이름이 곧 구조입니다.
- **링크**는 `[[문서 이름]]`. 이 링크가 모여 그래프가 됩니다.
- **서버**(Cloudflare Worker)가 저장·검색·그래프·히스토리를 맡고, 웹 앱(Vercel)과 MCP가 그 위에 얹혀 있습니다.

## 3. 시작하기

### 3.1 웹 앱 접속

1. 팀의 웹 주소를 엽니다 (예: `https://strata-sync-nine.vercel.app`).
2. 접속 방식은 둘 중 하나입니다.
   - **Google 로그인** — 서버에 Google 로그인이 켜져 있으면 버튼이 보입니다. 이 방식이어야 "나만 보기" 개인 문서를 쓸 수 있습니다.
   - **팀 토큰** — 서버 주소, 팀이 공유하는 토큰, 그리고 **내 이름**을 넣습니다. 이름은 내가 저장한 문서의 작성자로 남고, 팀원이 편지함에서 나를 부를 때 쓰는 이름입니다.
3. 접속하면 볼트가 브라우저에 내려오고(큰 볼트는 수십 초), 그래프가 뜹니다.

### 3.2 에이전트 연결 (Claude Code 기준)

설정 → **MCP** 탭에 내 이름이 들어간 명령이 준비돼 있습니다. 팀 토큰 방식이면 이런 모양입니다.

```bash
claude mcp add --transport http strata https://<worker>/mcp --header "Authorization: Bearer <팀 토큰>" --header "X-Author: 홍길동"
```

`X-Author`가 중요합니다. 서버는 이 이름으로 "누가 썼는지", "누구에게 온 편지인지"를 판단합니다. Google 로그인 서버라면 헤더 없이 `claude mcp add --transport http strata https://<worker>/mcp` 만 치면 로그인 창이 뜹니다.

연결되면 에이전트에게 이렇게 말해 보세요.

> "vault_me 해봐" → 내 책상(내 문서, 나에게 온 질문, 남들이 바꾼 것)이 나옵니다.

### 3.3 첫 10분

1. 그래프에서 아무 노드나 클릭 → 문서가 에디터에 열립니다. 위쪽 **속성** 표가 프런트매터입니다. 값을 바로 고칠 수 있습니다.
2. 본문에 `[[` 를 치면 문서 이름 자동완성이 뜹니다. 링크 하나 걸고 저장(자동 저장, 3초).
3. 상단 바의 **사람 아이콘** → 내 책상. 방금 저장한 문서가 "내가 최근 저장한 문서"에 있습니다.
4. 에이전트에게: "볼트에서 '소음 목표'에 대해 팀이 아는 걸 모아줘" → `vault_recall`이 관련 문서·이웃·멤버 메모를 한 묶음으로 가져옵니다.

## 4. 매일 쓰는 법

**아침** — 에이전트를 켜면 먼저 `vault_me`를 봅니다(서버가 그렇게 안내합니다). 팀원의 에이전트가 남긴 질문이 있으면 내 맥락(내 레포, 내 개인 문서)으로 답합니다. 앱에서는 내 책상의 "나에게 온 것"에 답변 상자가 있습니다.

**일하는 중** — 결정이 나면 문서로 씁니다. 에이전트가 대신 쓰게 하면 `_agent/`에 **제안**으로 들어가고, 사람이 승격해야 볼트에 들어갑니다. 에이전트는 남의 문서를 직접 고치지 않습니다.

**저장하는 순간** — 두 가지가 자동으로 돕니다.
- **AI 멤버 반응**: 그 문서를 담당 범위로 둔 AI 멤버(예: 사서, 디자이너)가 "이게 뭘 바꾸나 / 어디와 부딪히나 / 질문 하나"를 남깁니다. 에디터 오른쪽 Brain 패널에 보입니다.
- **모순 레이더**: 서버가 가장 가까운 문서들(다른 사람이 쓴 것 포함)과 비교해서 "동시에 참일 수 없는 것"을 찾으면 내 편지함에 질문을 넣습니다. "이 문서는 60 dB라는데 박의 문서는 65 dB — 어느 쪽?"

**누군가에게 물을 때** — 슬랙 대신 편지함. "이 파라미터 바꾸면 앱 쪽 영향 있어?"를 이의 이름으로 보내면, 이 또는 이의 에이전트가 다음에 켜질 때 그 사람 맥락으로 답합니다. 작업도 같은 방식으로 넘깁니다.

**릴레이** — 작업에 "다음 사람들"을 적어 두면(박 → 최), 이가 완료하는 순간 서버가 같은 작업을 박 앞으로 만들고 결과를 인용해 붙입니다. 일이 밤새 한 사람 컴퓨터에서 다음 사람 컴퓨터로 걸어갑니다. 모든 단계가 지정된 사람에게 갑니다 — 아무나 집어가는 구조가 아닙니다.

## 5. 기능

### 문서와 에디터
- **라이브 프리뷰**: 커서가 있는 줄만 마크다운 원문이 보이고 나머지는 렌더링됩니다. 제목·굵게·링크·체크박스·인용·콜아웃(`> [!warning]`)·표·코드블록·`#태그`.
- **속성 표**: 프런트매터가 키/값 표로. 텍스트·숫자·날짜·체크박스·리스트를 바로 고치면 해당 YAML 줄만 바뀝니다. "소스 편집"으로 원문도 볼 수 있습니다.
- **잠금 = 읽기 모드**: 자물쇠를 잠그면 전부 렌더링만 됩니다. 툴바 눈 아이콘으로 프리뷰/소스 전환.
- **이미지**: 붙여넣거나 끌어다 놓으면 `attachments/`에 저장되고 이미지 문서가 생깁니다. 설명은 에이전트가 보고 채웁니다(`images_undescribed`).
- **Brain 패널**: 이 문서에 멤버가 남긴 말, 버전 히스토리와 diff, 여기로 오는 링크·나가는 링크, 인용한 제안, 같은 동네 문서.

### 그래프
- 3D/2D 전환(설정 → 일반). 색은 역할·태그·폴더·활동(최근 편집이 따뜻하게)으로 바꿀 수 있습니다.
- 큰 볼트(수천 문서)도 됩니다. 라벨은 허브와 카메라 근처에만 붙고, 느린 기기에서는 자동으로 화질을 낮춥니다.
- **린트**(`graph_lint`): 참조는 되는데 문서가 없는 **팬텀 링크**, 아무도 안 가리키는 **고아**, 잘리면 그래프가 갈라지는 **다리 문서**, 클러스터 이동. 매일 새벽 `_reports/`에 리포트가 쌓입니다.

### 검색과 회상
- 검색은 BM25 + 시맨틱(임베딩)을 섞습니다. 한국어는 음절 2-gram으로 잘라서 조사에 덜 흔들립니다.
- `vault_recall`은 검색 결과에 링크 이웃, AI 멤버의 기억, 멤버가 남긴 말을 더해 "이 주제에 대해 팀이 아는 것"을 한 묶음으로 줍니다. 에이전트가 무언가 시작하기 전에 부르기 좋은 툴입니다.

### 히스토리
- 저장할 때마다 이전 버전이 보관됩니다(문서당 20개). Brain 패널이나 `vault_history`로 "누가 언제 무엇을 바꿨나"를 diff로 봅니다.

### 개인 문서 ("나만 보기")
- Google 로그인 사용자는 문서를 "나만 보기"로 둘 수 있습니다. 같은 볼트 안에 있고, 링크·그래프·검색·회상이 **나에게는** 그대로 작동하지만, 다른 사람과 다른 사람의 에이전트에게는 존재하지 않습니다. 개인 문서의 문장을 제안이나 멤버 기억에 그대로 옮기면 서버가 막습니다.

### AI 멤버
- 설정 → **AI 멤버**. 역할(사서, 디자이너, 리서처, PM…), 담당 범위(폴더·태그), 루틴(매일/매주), 그리고 자기 기억 노트 `_members/<이름> (memory).md`.
- 멤버의 "생각"은 각자의 에이전트에서 돌아갑니다: `/mcp__strata__member name=사서` 프롬프트를 부르면 역할·기억·오늘 할 루틴이 주어지고, 결과는 제안과 기억 노트로만 남깁니다.
- 서버에 모델 키가 있으면 저장 반응과 레이더가 서버에서 자동으로 돕니다.

### 내 책상과 편지함
- 상단 바 사람 아이콘, 또는 `?view=me` 링크(`vault_me`가 알려줍니다).
- 나에게 온 질문/작업, 내가 물은 것과 답, 내 문서에 온 멤버 반응, 내 문서를 인용한 제안, 남들이 최근 바꾼 것, 내 문서, 내 개인 문서.

## 6. MCP 툴

읽기: `vault_me`(내 책상) · `vault_recall`(주제에 대해 팀이 아는 것) · `vault_search` · `vault_read` · `vault_list` · `vault_changes`(언제부터 뭐가 바뀌었나) · `vault_history`(버전과 diff) · `vault_proposals` · `images_undescribed`

쓰기: `vault_propose`(제안 — 기본 쓰기 방식) · `vault_promote`(사람이 승인한 제안을 볼트로) · `vault_write`(직접 쓰기 — 부탁받았을 때만) · `vault_visibility`(개인 문서 공개/회수)

그래프: `graph_lint` · `graph_suggest_links`

사람 사이: `inbox_send`(팀원에게 질문/작업, `chain`으로 릴레이) · `inbox_list` · `inbox_reply` · `radar_check`(이 문서가 뭐랑 충돌하나)

AI 멤버: `members_list` · `member_remember`(기억 노트에 적기) · `member_report`(루틴 실행 기록) · 프롬프트 `member`

## 7. 관리

- **언어·테마·그래프·에디터**: 설정 → 일반. UI는 한국어/English, 기본은 브라우저 언어.
- **서버 배포**: `cd cloud && npx wrangler deploy`. 웹 앱은 GitHub에 푸시하면 Vercel이 자동 배포합니다.
- **모델 키**: 저장 반응과 레이더는 서버에 `ANTHROPIC_API_KEY`가 있어야 돕니다 — `cd cloud && npx wrangler secret put ANTHROPIC_API_KEY`. 없으면 멤버는 각자 에이전트에서만 돌고, 레이더는 쉽니다.
- **팀 토큰**: `wrangler secret put TEAM_TOKEN`. 바꾸면 모두 다시 접속해야 합니다.
- **시드 데이터**: 빈 볼트로 시작하기 심심하면 `node scripts/seed-product.mjs --server <worker> --token <토큰>` — 가상의 로봇청소기 회사 문서 수천 개가 들어갑니다(`--wipe`로 지우기).
- **Obsidian**: 볼트 폴더를 R2와 동기화하는 플러그인(Remotely Save 등)으로 붙이면 Obsidian에서 편집한 것도 서버가 색인합니다.

## 8. 자주 묻는 질문

**이름을 잘못 넣으면?** 팀 토큰 방식에서는 이름이 곧 나입니다. 설정 → 서버에서 바꿀 수 있고, MCP 쪽 `X-Author`도 같이 맞추세요. Google 로그인이면 계정으로 잡혀서 상관없습니다.

**개인 문서는 정말 안 보이나?** 서버가 경로 단위로 막습니다. 목록·검색·회상·히스토리·MCP 어느 길로도 남에게는 없는 문서입니다. 단, 팀 토큰 사용자는 개인 문서를 만들 수 없습니다(누구인지 확정할 수 없으니까요).

**에이전트가 내 문서를 마음대로 고치나?** 아니요. 기본 쓰기 통로는 제안(`_agent/`)이고, 사람이 승격합니다. 멤버는 자기 기억 노트만 직접 씁니다.

**오프라인은?** 웹 앱은 브라우저에 볼트 사본(IndexedDB)을 두고 15초마다 서버와 맞춥니다. 저장이 충돌하면 서버 버전이 남고 내 버전은 `(conflict 이름 시각).md`로 따로 저장됩니다.

**큰 볼트는 느리지 않나?** 5,000개 문서까지 확인했습니다. 첫 로딩은 수십 초, 이후는 변경분만 받습니다. 그래프는 노트북에서도 돌아가도록 자동으로 화질을 조절합니다.

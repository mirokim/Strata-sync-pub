## 구현 로드맵

### 1순위 — Edit Agent 인사이트 모드 ⭐ 가장 강력

현재 Edit Agent는 문서를 **하나씩** 보고 형식만 고친다. "인사이트 스윕" 사이클을 별도로 추가한다.

**동작 방식**
1. `graph_pagerank` 상위 10개 문서 + `graph_bridges` 노드 문서를 한꺼번에 로드
2. 시스템 프롬프트: *"이 문서들에서 인간이 놓치기 쉬운 패턴, 모순, 반복되는 신호를 찾아라. 형식 교정은 하지 않는다."*
3. 결과를 `_insights/weekly-YYYY-MM-DD.md`로 저장
4. Slack 채널에 요약 자동 발송 (선택)

**출력 형식 예시**
```markdown
# 인사이트 스윕 — 2026-03-30

## 반복 신호
- "맵 공략이 없다"는 지적이 2023, 2024, 2025 피드백에 3회 반복됨 → 해결 안 된 구조적 문제

## 모순
- 2024-12 MOBA 성장 제안은 15분 매치 기준 설계
- 2024-11 BR 제안은 나라카 블레이드(30분+) 기준 레퍼런스
- 두 모드가 같은 성장 시스템을 공유하면 템포 충돌 발생 가능

## 말해지지 않은 것
- 이사장님 피드백 어디에도 "리텐션"이나 "DAU" 언급 없음
  → 재미 품질에는 집중하나, 운영 지속성 설계는 아직 논의 시작 안 됨
```

**구현 범위**: `editAgentRunner.ts`에 `runInsightSweep()` 함수 추가, EditAgentTab에 "인사이트 스윕" 버튼 추가

### 2순위 — 외부 게임 레퍼런스 데이터 자동 수집 ⭐ 코드 변경 없이 즉시 효과

AI는 볼트 안에 있는 것만 참조한다. `_reference/games/` 폴더에 경쟁작 분석 문서를 추가하면 RAG가 자연스럽게 교차 참조한다.

**수집 대상 (Steam 공개 API)**

| 게임 | 선정 이유 | Steam AppID |
|------|-----------|-------------|
| The Finals | 파괴 환경 + 집단 팀전 — 샌드박스 PvP 구조 가장 유사 | 2073850 |
| Heroes of the Storm | 팀 중심 MOBA 성공·실패 교훈 (개인 캐리 제거) | 2918250 |
| Predecessor | 3인칭 MOBA 실패 사례 (Paragon 유산) | 1609850 |
| Battlerite | 레인 없는 순수 팀 아레나 — 집단 PvP 핵심 구조 | 504370 |
| Gigantic: Rampage | 집단전 + 수호 구조 — 실패 원인 분석 | 2440510 |
| Deadlock | 볼트에 언급됨, 심층 분석 필요 | 1422450 |
| Naraka: Bladepoint | BR 레퍼런스로 이미 사용 중, 정형화 필요 | 1175440 |
| Marvel Rivals | 히어로 슈터 비교 기준 (볼트 내 분석 보완) | 2767030 |

**수집 데이터**: 게임 설명, 장르 태그, Steam 리뷰 요약, 평점, 주요 메카닉 키워드

**저장 형식**
```
_reference/
  games/
    [게임] The Finals.md
    [게임] Heroes of the Storm.md
    ...
```

#### 데이터 오염 방지 — 3중 인지 구조

외부 레퍼런스 데이터는 **비교 분석 효과가 매우 크지만**, AI가 내부 프로젝트 문서와 혼동하면 치명적이다. 아래 3중 구조로 방어한다.

**1단계 — Frontmatter 스키마 표준화**

모든 레퍼런스 문서에 아래 필드를 필수 포함한다. RAG/그래프 필터의 기계적 기준이 된다.

```yaml
---
type: external-reference        # 핵심 필터 키 — 그래프/인사이트에서 자동 제외
ref_game: "The Finals"          # 어떤 게임인지
ref_source: steam               # 데이터 출처 (steam / metacritic / igdb)
ref_collected: 2026-03-30       # 수집일 (오래된 데이터 경고에 활용)
ref_version: "Season 4"         # 게임 버전 (업데이트로 무효화될 수 있음)
internal: false                 # 내부 문서 여부 명시
---
```

**2단계 — 문서 상단 강제 마커**

AI가 본문을 읽기 시작하는 순간 바로 인지하도록 모든 레퍼런스 문서 상단에 고정 삽입한다.

```markdown
> ⚠️ **[외부 레퍼런스]** 이 문서는 **The Finals** (외부 출시 게임)에 대한 데이터입니다.
> 프로젝트 A 내부 의사결정 근거로 **직접 인용 금지**.
> 비교 분석 컨텍스트로만 활용하세요.
> 출처: Steam API | 수집일: 2026-03-30 | 버전: Season 4
```

**3단계 — RAG 반환 시 자동 래퍼 주입**

`rag_electron.py` 검색 결과 반환 단계에서 `type: external-reference` 문서에 래퍼 텍스트를 자동 삽입한다. AI가 컨텍스트 중간에서 읽어도 혼동하지 않는다.

```
[외부게임 레퍼런스 — The Finals / Steam 수집 / 2026-03-30]
{문서 내용}
[끝 — 위는 외부 게임 데이터이며 프로젝트A 내부 문서가 아님]
```

**그래프 분리 원칙**
- PageRank / Bridge / Cluster 계산 시 `type: external-reference` 문서 **자동 제외** → 내부 중요도 왜곡 방지
- 인사이트 스윕 **1단계(내부 패턴 분석)** 에서 제외, **2단계(외부 비교)** 에서만 명시적으로 로드
- 레퍼런스 문서는 내부 문서에서 wikilink로 연결하지 않음 → 그래프 오염 원천 차단

**구현 범위**: `bot/tools/fetch_game_reference.py` 신규 작성 (~150줄), frontmatter + 마커 자동 삽입 포함

### 3순위 — chief_director 프롬프트 인사이트 강화

현재 프롬프트는 PM 역할 + 실행 중심이다. 인사이트 레이어를 추가한다.

**추가할 지침**
```
- 문서들 사이의 모순이나 긴장 관계를 명시적으로 찾아라
- 여러 피드백에서 반복되는 신호는 강조하라 ("N회 반복됨" 명시)
- "말해지지 않은 것" (피드백에 없지만 있어야 할 것)을 지적하라
- 게임 업계 일반 패턴과 비교해 이 프로젝트의 특이점을 짚어라
- _reference/games/ 문서가 컨텍스트에 있을 때, 경쟁작과의 차이를 자동으로 연결하라
```

**구현 범위**: `src/lib/personaPrompts.ts` `chief_director` 항목 수정

### 4순위 — 이사장님 피드백 시간축 분석 ⚠️ 조건부 적용

> **데이터 오염 주의**: 2019~2026년 7년간 게임 설계 자체가 크게 변경됐을 가능성이 높다.
> 초기 피드백(크래프팅/영혼 시스템)과 현재 피드백(MOBA/영웅 스킬 교체)은 사실상 **다른 게임**에 대한 의견일 수 있다.
> 시계열 단순 비교 시 "7년째 같은 우려 반복"처럼 **잘못된 패턴 감지** 위험이 있다.

**적용 조건**
- 분석 범위를 **게임 방향성 수렴 이후 시점으로 한정** (예: MOBA 모드 확정 이후, 2024년 이후만)
- 또는 문서에 **게임 버전/마일스톤 태그**(`milestone: MOBA-확정` 등)가 붙은 경우에만 교차 비교
- AI에게 "이 시기에 게임 설계가 바뀌었을 수 있으니 단순 반복 판단은 하지 말라"는 제약 명시

**실용적인 대안**: 시간축 전체 분석 대신, **최근 1년(2025~2026) 내 피드백 패턴 분석**으로 범위 축소

**구현 방식**: 인사이트 스윕의 옵션 파라미터로 `dateFrom`을 받아 범위 제한

### 5순위 — 그래프 분석 결과의 인사이트 활용 (신규 제안)

현재 `graph_pagerank`, `graph_clusters`, `graph_bridges`가 계산되고 있지만 숫자만 노출된다. 이 결과를 **의미 있는 인사이트**로 변환하는 레이어가 없다.

**예시 인사이트 변환**

| 그래프 지표 | 현재 | 인사이트 변환 |
|-------------|------|---------------|
| PageRank 1위 문서 | `_index.md` | "허브가 인덱스 파일뿐 — 실제 콘텐츠 허브 부재" |
| Bridge 노드 | 특정 캐릭터 문서 | "다이잔 캐릭터가 여러 클러스터를 연결 — 세계관 SSOT 역할" |
| 고립 문서 | 특정 레퍼런스 | "연결 없는 레퍼런스는 실제로 의사결정에 반영 안 된 것" |
| 급증 링크 | 신규 문서 | "최근 추가된 문서에 링크가 몰리면 핫 토픽 감지" |

**구현 범위**: `runInsightSweep()`에서 그래프 결과를 프롬프트에 주입하는 로직 포함

---

### 6순위 — 감정·톤 변화 감지 (신규 제안)

이사장님 피드백 문서에서 **어조의 변화**를 감지한다. 단순 키워드가 아니라 긴장감의 변화를 읽는 것.

**감지 패턴**
- "우려", "보류", "진행X" 등 부정 신호 빈도
- "좋은 아이디어", "괜찮을 것 같음" 등 긍정 신호 빈도
- 같은 주제에 대한 톤이 연도별로 어떻게 변화했는가

**활용**: 특정 기능이 이사장님의 관심에서 멀어지고 있는지, 혹은 관심이 높아지는 신호인지 조기 감지

---

### 7순위 — "설계 공백" 자동 탐지 (신규 제안)

볼트를 전체적으로 읽었을 때 **있어야 할 문서가 없는 것**을 찾는다.

**예시 공백 (볼트에서 확인됨)**
- MOBA 모드와 BR 모드 사이의 **공유 성장 시스템 설계서** — 두 모드가 별도 제안만 있고 통합 설계 없음
- **리텐션 설계 문서** — 피드백에서 한 번도 언급 안 됨
- **모드 선택 UX 흐름** — 두 모드가 있는데 진입 경험 설계 문서 없음

**구현 방식**: 인사이트 스윕 출력에 "설계 공백" 섹션 포함

## 구현 우선순위 요약

```
즉시 효과 (코드 없음)     → 2순위: _reference/games/ 폴더 + 게임 데이터 스크립트
단기 구현 (1~2일)         → 3순위: chief_director 프롬프트 수정
중기 구현 (3~5일)         → 1순위: Edit Agent 인사이트 스윕 모드
중기 구현 (3~5일)         → 5순위: 그래프 인사이트 변환 레이어
장기 구현 (1~2주)         → 4순위: 시간축 분석 자동화
장기 구현 (1~2주)         → 6순위: 감정·톤 변화 감지
상시 운영                  → 7순위: 설계 공백 탐지 (인사이트 스윕에 통합)
```

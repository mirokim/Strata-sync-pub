# AI 검색 품질 & 추론 향상 제안 (2026-03-27)

## 1. 검색 품질 향상

### 현재 구조의 병목
파이프라인: `직접검색 → 벡터(Gemini) → BM25 보완 → BFS 그래프`

| # | 방법 | 설명 | 임팩트 | 난이도 |
|---|---|---|---|---|
| 1 | **RAG-Fusion (Multi-Query)** | LLM이 3가지 관점 쿼리 생성 → 각각 검색 → RRF 합산. 쿼리 표현 운에서 해방 | ★★★★ | ★★★ |
| 2 | **청크 단위 벡터 검색** | 문서 전체 → 400~600자 청크 분할 임베딩. 긴 문서 뒷부분 누락 해소. 벡터 캐시 구조 변경 필요 | ★★★★★ | ★★★★ |
| 3 | **HyDE** (Hypothetical Document Embeddings) | 쿼리 임베딩 대신 "이상적인 답변 문서"를 LLM이 생성 후 임베딩. 쿼리-문서 공간 미스매치 해소 | ★★★★ | ★★ |
| 4 | **그래프 중심성 부스트** | PageRank 값을 검색 점수에 10~20% 가중. 자주 참조되는 핵심 문서 자동 우선순위 | ★★★ | ★★ |
| 5 | **최신 문서 핫 인덱스** | 최근 30/90일 문서를 별도 인덱스로 유지, 최신 인텐트 시 우선 탐색 | ★★★ | ★★ |

## 2. AI 추론·인사이트 향상

### 현재 구조의 병목
현재: 컨텍스트 수집 → 단일 LLM 호출 → 스트리밍 응답

| # | 방법 | 설명 | 임팩트 | 난이도 |
|---|---|---|---|---|
| 1 | **구조화된 추론 프롬프트** | 응답 구조 강제: [관련 문서 요약] → [패턴/연결고리] → [분석] → [결론/제안]. LLM의 "요약만 하고 끝" 방지 | ★★★★ | ★ |
| 2 | **Extended Thinking** | Claude API `thinking: { type: "enabled", budget_tokens: 8000 }`. 복잡한 설계 분석/의사결정에서 효과 큼 | ★★★★ | ★★ |
| 3 | **ReAct 패턴** | LLM이 부족한 정보를 명시 → 봇이 추가 검색 후 재주입 루프. 다단계 추론 질문에 효과적 | ★★★★ | ★★★★ |
| 4 | **다중 페르소나 크로스-체킹** | 복잡한 질문에 2개 페르소나가 각각 분석 후 합성. 주관적 판단 편향 감소 | ★★★ | ★★★ |
| 5 | **자동 메모리 누적** | 대화 중 발견된 중요 사실을 자동으로 장기 메모리에 기록. 연속 대화 맥락 유지 | ★★★ | ★★★ |
